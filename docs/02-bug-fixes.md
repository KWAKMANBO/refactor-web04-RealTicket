# 2. 전환하며 고친 문제

NestJS 코드를 옮기면서 발견해 고친 문제들이다. Node는 스레드 하나로 동작해 드러나지 않던 경쟁 조건이, 멀티스레드인 Java에서는 실제 버그가 되므로 특히 동시성 문제를 중점적으로 다뤘다.

## 동시성

| 문제 | 원인 | 해결 | 검증 |
|---|---|---|---|
| 정원보다 많이 입장 | 인원 확인과 대기열 pop 사이에 다른 요청이 끼어듦 | `try_enter`, `admit_waiting` Lua로 원자 처리 | 40명 동시 요청, 정원 5 → 정확히 5명 입장, 나머지는 1~35번 대기 번호를 겹치지 않게 받음. 좌석 선택 중 3명이 동시에 떠나도 정확히 3명만 입장 |
| 설정 인원보다 많은 좌석 선점 | "선점 수 확인 → 좌석 예약"이 분리됨 (좌석 하나의 예약 자체는 Nest도 Lua로 원자 처리하고 있었음) | `reserve_seat` Lua에서 인원 확인까지 함께 처리 | 인원 2명인 사용자가 좌석 6개를 동시에 요청 → 정확히 2개만 성공 |
| 세션 값 덮어쓰기 | 세션을 JSON 문자열로 저장해 "읽기 → 수정 → 쓰기" 사이에 다른 요청이 끼면 상태·예매 대상이 서로 덮어씀 | Redis Hash로 필드 단위 갱신, 조건부 갱신은 Lua | 세션 저장소 테스트 |
| 같은 예매가 두 번 저장 | 예매 확정 요청이 중복으로 오면 둘 다 저장 | `mark_saved` Lua로 저장 시작을 먼저 표시, 실패 시 되돌림 | 같은 요청 두 번 → 두 번째 400, 예매 1건 |

같은 좌석을 30명이 동시에 선점하면 1명만 성공하는지도 테스트로 확인했다 (Nest에서도 지켜지던 동작이 Java에서도 유지되는지 확인).

## 예매 흐름

| 문제 | 원인 | 해결 |
|---|---|---|
| 오픈 시각 전 이벤트가 열림 | `validateOpeningEvent`의 반환값을 무시 | 오픈 시각 전이면 예약만 하고 열지 않음 |
| 한 이벤트를 마감하면 **다른 이벤트의 입장자까지 삭제** | `entering:*` 패턴으로 모든 이벤트의 키를 지움 | 이벤트 단위 키 설계, 해당 이벤트 키만 삭제 |
| 마감 후에도 브로드캐스트 interval이 계속 돎 | 이벤트별 `setInterval`을 해제하지 않음 | 전역 주기 하나 + 채널 단위 관리 |
| 개발 환경 설정값이 한 번도 쓰이지 않음 | `NODE_ENV === 'prod' \|\| 'prod-in-dev'` 조건이 항상 참 | 프로필별 설정(`application-{profile}.yml`) |
| 서버 재시작 후 SSE 구독 실패 | 구독 객체가 메모리에만 있어 재시작 후 없음 (대기열 SSE는 첫 대기자 전에 구독하면 500) | 구독 채널을 필요할 때 생성 |
| 예매 확정 후 좌석이 영영 풀리지 않음 | 확정 후 좌석을 더 선점하고 나가면, 확정 표시 때문에 해제하지 않음 | 확정 후 좌석 변경 차단 |
| 좌석 SSE 재연결 시 선점 정보 초기화 | 재연결 때마다 좌석 선택 세션을 새로 만들어 선점 기록이 사라지고 좌석은 잠긴 채 남음 | 이미 좌석 선택 중이면 유지, 연결 교체는 "떠남"으로 처리하지 않음 |
| 대기열 새치기 | 빈자리가 생기는 순간 새로 온 사용자가 대기자보다 먼저 입장 가능 | 대기자가 있으면 새 사용자는 대기열 뒤로 |
| 대기 중 재요청 시 번호 중복 발급 | 요청마다 대기열에 다시 추가 | sid별 번호를 저장해 같은 번호 반환 |
| 만료된 세션이 TTL 없이 되살아남 | 상태 갱신 시 세션이 없어도 새로 씀 | 세션이 있을 때만 갱신 (Lua) |
| Redis를 멈출 수 있는 `KEYS` 명령 | 패턴 검색으로 키 삭제 | 이벤트 단위 키로 정확히 삭제 |
| 좌석 조회가 Redis를 오래 점유 | Lua 안에서 좌석마다 `GETBIT` (좌석 수만큼 반복) | 구역 비트맵을 파이프라인으로 한 번에 읽어 Java에서 해석 |

## 인증·보안

| 문제 | 해결 |
|---|---|
| **인증 없이 누구나 관리자 계정 생성 가능** (`POST /user/signup/admin`) | `ADMIN_SIGNUP_ENABLED`가 켜진 환경에서만 동작 (dev 켜짐, prod 꺼짐), 꺼져 있으면 404 |
| 비밀번호가 틀려도 그 계정의 기존 세션이 끊김 (남이 틀린 비밀번호로 시도만 해도 로그아웃됨) | 로그인 성공 시에만 기존 세션 종료 |
| 로그아웃해도 쿠키가 남음 | `SID` 쿠키 만료 |
| 운영 서버에 mock API(`/mock/**`)가 열려 있음 | mock 제거 |
| 항상 `true`를 반환하는 미사용 `AuthGuard` | 옮기지 않음 |

## API·데이터

| 문제 | 원인 | 해결 |
|---|---|---|
| 의도와 다른 에러 코드 | `error instanceof A \|\| B` 조건이 항상 참이라 모든 예외가 그대로 나감 | 의도한 400/404/409로 정리 |
| 없는 장소 조회 시 500 | try/catch가 모든 예외를 500으로 감쌈 | 400 |
| `GET /event/:id`의 `name`이 비어 있음 (프런트는 화면에 표시) | 존재하지 않는 필드를 펼침 | 프로그램 이름을 채움 |
| 프로그램이 쓰는 장소 삭제 시 500 | 외래 키 오류를 처리하지 않음 | 409와 안내 메시지 |
| 게스트 정리 실패 가능 | 취소된(soft delete) 예약이 외래 키로 남아 사용자 삭제 실패 | 좌석 → 예약 → 사용자 순서로 native 삭제 |
| 예매 내역 조회 N+1 | lazy 관계를 예매마다 개별 조회 | fetch join + batch fetch |
